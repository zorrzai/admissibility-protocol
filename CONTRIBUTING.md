# Contributing to the Admissibility Protocol

## Filing a comment

Open an [Issue](https://github.com/zorrzai/admissibility-protocol/issues/new?template=comment-on-amendment.md)
using the **Comment on a proposed amendment** template. State the clause you
are commenting on. §14 of the current draft lists eight questions where
comment is specifically sought.

## What happens to a comment

Every substantive comment is dispositioned in public — accepted, rejected or
deferred, with reasoning — before adoption. Rejected comments are published
alongside accepted ones. The process is specified at §10.5.1 of the draft;
this file does not restate it.

## Versioning

Specified at §0.4. A revision that clarifies or hardens without altering the
dimensions or the conformance bar increments the version. A change to either
is published as a successor protocol, not a version of this one. Prior
versions remain permanently citable.

## What this repository does not do

It issues no certification, maintains no registry, grants no seal, and
charges no fee (§10.4). Any party may run AP-1 against any system, including
the author's, without permission or notification.
